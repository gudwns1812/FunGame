# 실행 계획: 멜론 차트 인기곡을 매일 곡 대기열에 넣는다

작성 2026-11-10
대상: `backend` `infra`

이 문서가 유일한 계획이다. **남은 일만 적는다.** 끝난 작업은 지우고 코드와 커밋에 맡긴다.

---

## 1. 결정

### 1.1 Lambda 가 아니라 앱 안 스케줄러로 돌린다

| 이유 | 내용 |
|---|---|
| 중복 실행 | Redis ShedLock 이 이미 있다. `@SchedulerLock` 만 붙이고 메서드 안에서 게이트를 보지 않는다 (BACKEND.md 7번) |
| 유튜브 링크 | `song_scrape_request` 에 넣기만 하면 기존 `SongScrapeScheduler` 가 링크를 채워 `song_entity` 로 옮긴다. 이 흐름은 고치지 않는다 |
| DB · 인터넷 | Lambda 가 EC2 의 MySQL 에 닿으려면 VPC 안에 들어가야 하고, 그러면 NAT 게이트웨이(월 약 $43) 없이는 멜론 · Gemini 에 못 나간다 |
| 모니터링 | 로그 · 지표가 기존 Loki · 프로메테우스 · 디스코드 알림에 그대로 잡힌다 |

### 1.2 흐름

매일 12:00 (`zone = "Asia/Seoul"` — 앱에 시간대 설정이 없어 빼면 서버 시간대를 따른다)

| 순서 | 하는 일 | 위치 |
|---|---|---|
| 1 | 차트 100곡(멜론 곡 id · 제목 · 가수)과 좋아요 수를 가져온다 | `client-melon` |
| 2 | 좋아요 5만 이상만 남기고 제목을 정리한다 | 도메인 `ChartSong` |
| 3 | `(가수, 제목)` 이 `song_entity` · `song_scrape_request` 에 있으면 뺀다 | `SongService` |
| 4 | 남은 곡만 상세 페이지에서 발매일 · 장르를 가져온다. **하루 30곡까지** | `client-melon` |
| 5 | 한글이 아닌 글자가 든 제목만 모아 Gemini 를 **한 번** 부른다 → 한글 독음 · 정답 별칭 | `client-gemini` |
| 6 | 초성 힌트를 계산해 `song_scrape_request` 에 넣는다. 넣을 때 `(제목, 발매일)` 까지 보고 겹치면 뺀다 | 도메인 `Choseong`, `SongService.enqueueIfNew` |

- 상세 조회를 하루 30곡으로 끊는 이유: `@Scheduled` 는 `app-sched-` 풀 5개를 하트비트 · 로비 알림과 나눠 쓴다.
  첫 실행에 새 곡이 100곡이어도 한 번에 2분을 넘기지 않게 하고, 나머지는 다음 날들에 들어온다.
- 멜론 요청 사이는 1초 쉰다.

### 1.3 곡 정보는 이렇게 채운다

| 필드 | 값 |
|---|---|
| `title` | 아래 제목 정리 표를 거친 것. 정답 판정이 완전 일치라 괄호가 붙어 있으면 아무도 못 맞힌다 |
| `singer` | 멜론 표기에서 NBSP 를 공백으로 바꾼 것(`RESCENE (리센느)`). 여럿이면 멜론 순서대로 `, ` 로 잇는다 |
| `releaseDate` | 상세 페이지 `발매일` (`2021.10.11`) |
| `categories` | 1.4 표 |
| `playSeconds` | `0` — 관리자 곡 추가와 같다 |
| `answers` | 제목 · 괄호 속 별칭, 한글 제목이 아니면 Gemini 독음 · 비슷한 독음까지. 모두 **글자 · 숫자만 남기고 영어는 소문자**로 바꿔 넣는다(`HOME SWEET HOME` → `homesweethome` · `홈스윗홈` · `홈스위트홈`). 채팅 안내가 띄어쓰기 없이 소문자로 치라고 하고, 판정은 완전 일치다. 원래 모양 제목은 `Song.of` 가 넣는다 |
| `hint` | 한글 제목이면 그 제목의 초성, 아니면 Gemini 독음의 초성 |

제목 정리 (2026-11-10 차트 표본 기준)

| 멜론 표기 | 정리 |
|---|---|
| `HOME SWEET HOME (feat. 태양, 대성)` · `삐그덕 (Feat. 아이유)` · `모르시나요(PROD.로코베리)` · `퇴사할게여 (Narr. 기안84)` | 참여 표기 괄호(`feat.` · `prod.` · `narr.` · `with`, 대소문자 무시, 앞 공백 없어도)를 뗀다 |
| `Seven (feat. Latto) - Clean Ver.` | ` - … Ver.` 꼬리를 뗀다 |
| `백화요란 (Inside Out)` · `뛰어(JUMP)` · `404 (New Era)` | 괄호 앞이 제목, 괄호 안은 정답 별칭 |
| `그대만 있다면 (여름날 우리 X 너드커넥션 (Nerd Connection))` | 괄호 앞이 제목. 괄호 안에 괄호가 또 있으면 별칭으로 쓰지 않는다 |
| `It′s Me` | `′` · `’` 를 `'` 로 |

- **한글 제목**: 한글 음절이 하나 이상 있고, 글자(`Character.isLetter`)가 전부 한글 음절인 것. 숫자 · 공백 · 문장부호는 따지지 않는다.
  `0+0` · `404` 처럼 한글이 없는 제목은 힌트가 곧 정답이 되므로 Gemini 쪽으로 보낸다.
- **초성**: 한글 음절은 초성으로 바꾸고 공백은 뺀다. 숫자 · 문장부호는 그대로 둔다. `밤양갱` → `ㅂㅇㄱ`, `HOME SWEET HOME` → `홈 스윗 홈` → `ㅎㅅㅇㅎ`.
- 힌트 화면은 `가수 - 힌트` 로 보이므로(`SongQuiz.getHint`) 힌트에 가수를 넣지 않는다.
- 독음을 정답에도 넣는 이유: 힌트 `ㅅㅍㄴㅂ` 를 본 사람은 `슈퍼노바` 를 친다. 정답에 없으면 오답이 된다.

### 1.4 장르 → 카테고리

| 멜론 장르 | 카테고리 |
|---|---|
| `POP` 이 있으면 | `POP` 하나 |
| `J-POP` 이 있으면 | `JPOP` 하나 |
| 그 밖 | `KPOP` + 아래 대응을 모두 |
| `발라드` | `BALLAD` |
| `댄스` | `DANCE` |
| `랩/힙합` | `RAP` |
| `R&B/Soul` | `RNB` |
| `록/메탈` · `인디음악` | `ROCK` (관리자 화면 표기가 `록/인디`) |
| `국내드라마` · `국내영화` · `애니메이션/웹툰` | `OST` |
| 대응 없음 (트로트 · 포크 등) | `KPOP` 만 |

장르는 상세 페이지에 `발라드, 국내드라마` 처럼 쉼표로 여러 개 온다. `POP` · `애니메이션/웹툰` · `댄스` · `발라드` 는 표본에서 확인했다.

### 1.5 Gemini 호출

| 항목 | 내용 |
|---|---|
| 횟수 | 하루 최대 1회. 한글이 아닌 새 곡이 없으면 부르지 않는다 |
| 방식 | REST `generateContent` 를 `RestClient` 로 직접 부른다. SDK 를 쓰지 않는다 — `client-discord` 와 같은 방식이고 `MockRestServiceServer` 로 테스트한다 |
| 출력 | `responseMimeType: application/json` + `responseSchema` 로 `[{id, pronunciation, aliases[]}]` 를 고정한다. `pronunciation` 은 힌트에 쓸 가장 흔한 독음, `aliases` 는 비슷한 다른 독음(`홈스위트홈` · `위플래쉬`) |
| 검증 | 독음은 글자가 전부 한글이어야 한다. 별칭은 빈 값 · 중복을 빼고 8개까지. 통과 못 한 곡은 그날 넣지 않는다 |
| 실패 · 한도 초과 · 키 없음 | 한글이 아닌 곡은 **그날 넣지 않고 다음 날 다시 시도**한다. 5만 넘은 곡은 차트에 며칠 남는다. 한글 제목 곡은 영향 없이 들어간다 |
| 설정 | `client.gemini.model`, `client.gemini.api-key`. 키 기본값은 빈 문자열이라 키가 없어도 앱이 뜬다. 모델 이름과 무료 일일 한도는 작업 5 에서 AI Studio 를 보고 정한다 |

### 1.6 실패해도 서비스에 영향이 없다

- 수집은 예외를 밖으로 던지지 않는다. 한 곡이 실패하면 그 곡만 건너뛴다.
- `lockAtMostFor = PT10M`, `lockAtLeastFor = PT1M`.
- 실행마다 결과 한 줄 로그(차트 N · 5만 이상 M · 새 곡 K · 넣음 J · 미룸 D)와 지표를 남긴다.

| 지표 | 값 |
|---|---|
| `fungame.melon.chart.runs{result}` | `ok` · `empty`(차트에서 0곡 — 멜론 HTML 이 바뀐 신호) · `failed`(멜론 요청 실패) · `gemini_failed` |
| `fungame.melon.chart.songs{stage}` | `popular` · `enqueued` · `deferred` |

카운터는 **기동할 때 모든 태그 값을 0 으로 등록**한다. 처음 생긴 카운터의 첫 값은 `increase()` 가 잡지 못한다.

### 1.7 하지 않는 것

| 하지 않는 것 | 이유 |
|---|---|
| 멜론 곡 id 컬럼 | 기존 `(가수, 제목)` · `(제목, 발매일)` 중복 판정으로 충분하다. 스키마를 바꾸지 않아 배포는 한 번이다 |
| 차트에서 빠진 곡 삭제 | 한 번 들어온 곡은 계속 쓴다 |
| 관리자 검수 단계 | 기존 신고(`초성 힌트가 이상해요` · `답이 이상해요`)로 잡는다 |
| 이미 있는 곡의 힌트 · 정답 보정 | 새 곡만 다룬다 |
