# 실행 계획: 공동 순위를 매기고 판 결과를 전적으로 남긴다

작성 2026-10-09
대상: `backend` `frontend`

이 문서가 유일한 계획이다. **남은 일만 적는다.** 끝난 작업은 지우고 코드와 커밋에 맡긴다.

---

## 1. 결정

### 1.1 동점이면 같은 순위다

지금은 점수가 같으면 `memberId` 가 작은 사람, 즉 먼저 가입한 사람이 앞 순위를 받는다. 결과 화면도 정렬 순서대로
`idx + 1` 위를 붙여 같은 점수가 1위와 2위로 갈린다. 공정하지 않다.

- 점수가 같으면 같은 순위다. 다음 순위는 그 인원만큼 건너뛴다. 10 · 10 · 7 점이면 1 · 1 · 3 위다.
- 순위와 우승 여부는 백엔드 `GameRank` · `PlayerScore` 한 곳에서 매긴다. 프론트는 서버가 준 `rank` · `winner` 를
  그대로 보이고 다시 계산하지 않는다. 결과 화면과 전적이 같은 값을 쓴다.
- 같은 순위 안의 표시 순서는 `memberId` 로 고정한다. 순위에는 영향이 없다.
- 프론트가 서버 값에 기대므로 **백엔드를 먼저 배포**하고 프론트 PR 을 그 뒤에 머지한다.

### 1.2 승패는 결과에서 계산하고, 원본을 저장한다

승수 칸을 올리지 않는다. 판마다 참가자별 결과를 남기고 요약은 조회할 때 집계한다.

| 게임 | 승리 | 패배 |
| --- | --- | --- |
| 노래 퀴즈 · CS 퀴즈 | 끝까지 남은 1위 (공동 포함) | 나머지, 탈주자 |
| 행맨 (협동) | 성공 시 끝까지 남은 전원 | 실패 시 전원, 탈주자 |

- 탈주자는 점수와 상관없이 끝까지 남은 사람들보다 아래 순위이고 패배다.
- 1위 점수가 0 점이면(아무도 못 맞힘) 승자가 없다. 순위는 전원 1위지만 `PlayerScore.isWinner()` 가 거짓이고,
  결과 화면은 "우승자 없음" 을 보인다. 전적은 전원 패배다.
- 시작 인원이 1명인 판은 기록하지 않는다.

### 1.3 같은 판은 한 번만 저장한다

`SHOW_RESULT` 예약 작업은 점유 기한(`GameTimer.LEASE`)이 지나면 다른 인스턴스가 다시 실행한다. 판을 시작할 때
판 id 를 만들어 스냅샷에 넣고 DB 에 고유 제약을 건다. `roomId` 는 판이 바뀌어도 같아 쓸 수 없다.

### 1.4 저장이 실패해도 판은 끝난다

지금의 `try { 결과 발행 } finally { endGame }` 원칙을 저장에도 적용한다. 저장 실패는 로그로 남기고 방을 풀어 준다.

### 1.5 하지 않는 것

- 판별 상세 기록 화면. 이번에는 전적 요약만 만든다.
- 레이팅 · 점수 누적 같은 다른 지표.

## 3. 전적 저장과 요약 (공동 순위 머지 뒤)

1. **판 id** — 판을 시작할 때 만들어 `GameSnapshot` 에 넣는다. 배포 중 옛 스냅샷에는 없으니
   `StoredShapeCompatibilityTest` 로 읽기 호환을 확인하고, id 가 없는 판은 기록하지 않는다.
2. **결과 판정** — 순수 도메인 객체가 §1.2 규칙으로 참가자별 승패 · 순위 · 탈주 여부를 낸다. 점수제의 우승은
   `PlayerScore.isWinner()` 를 그대로 쓴다. 테스트를 먼저 쓴다.
   행맨이 탈주자를 기억하는지(`HangmanQuiz.initPlayers` 이후) 먼저 확인한다.
3. **테이블** — Flyway 로 추가한다.
   - `game_record` — 판 id (고유), 게임 종류, 시작 · 종료 시각, 시작 인원
   - `game_record_player` — 판, 회원 id, 승패, 순위, 점수, 탈주 여부. `(member_id, game_type)` 조회 인덱스
4. **저장** — `QuizGameService.showResult` · `HangmanGameService.submitResult` 에서 결과 발행과 같은 자리에 둔다.
   고유 제약 위반은 이미 저장된 판으로 보고 넘어간다.
5. **조회 API** — 내 전적 요약. 게임 종류별 판수 · 승 · 패 · 승률. 명세를 `api/` 에 추가한다.
6. **프론트** — 전적 요약을 보여 줄 자리를 정한 뒤 붙인다.
