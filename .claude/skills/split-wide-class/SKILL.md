# 넓은 클래스는 쪼갤 후보다

```
인스턴스 필드 > 7      또는      생성자 인자 > 4
```

걸렸다고 반드시 쪼개는 것은 아니다. **멈춰서 보라는 신호**다.

## 숫자는 어디서 왔나

책에는 필드 개수 기준이 없다. *Clean Code* 는 클래스를 **책임**으로 재고(“25단어로,
`if`·`and`·`or`·`but` 없이 설명할 수 있어야 한다”), *Refactoring* 의 **Large Class** 냄새도
“인스턴스 변수가 너무 많으면 여러 일을 한다”까지만 쓴다.

숫자를 주는 쪽은 도구와 메트릭이다.

| 출처 | 기준 |
|---|---|
| Clean Code — 함수 인자 | 3 초과는 “아주 특별한 정당화” |
| Lanza & Marinescu, God Class 의 NOA | 5 |
| PMD `TooManyFields` | 15 |
| SonarQube S1820 | 20 |

**우리 집 숫자는 필드 7, 인자 4다.** 인자 4는 Clean Code 의 3 에 생성자 주입 현실을 한 칸
더한 것이고, 필드 7 은 Lanza 의 5 와 PMD 의 15 사이에서 잡았다.

PMD 와 Sonar 기본값은 우리에게 너무 헐겁다. `RedisStreamSpreader` 가 **필드 13개**였을 때
둘 다 통과한다. 그때 실제로 걸린 것은 **생성자 인자 7개**였다.

## 숫자보다 잘 듣는 신호 세 가지

숫자는 놓치는 것이 많다. 세는 것을 멈추고 이걸 본다.

**① 한 협력자가 서로 다른 관심사 여러 곳에 쓰인다.**
`RedisStreamSpreader` 의 `clock` 이 큐 적재 시각 · 나이 검사 · 트림 커트오프 세 군데에
쓰였다. 세 관심사가 한 클래스에 있다는 뜻이었다.

**② 한 문장으로 설명할 때 “그리고” 가 들어간다.**
“메시지를 만들고 큐에 넣고 워커로 꺼내 Redis 에 쓰고 지표를 낸다” — 네 개다.

**③ 지표나 로그가 그걸 만든 원인과 다른 클래스에 있다.**
`dropped` 를 원인별로 세는 쪽에 돌려주니 별도 지표 클래스가 필요 없어졌고,
그 과정에서 직렬화 실패가 Redis 실패에 묻혀 있던 것이 드러났다.
**경계를 잘 그으면 안 보이던 결함이 나온다.**

## 쪼갤 때

1. 필드를 **같이 쓰이는 것끼리** 묶는다. 한 메서드에서만 함께 등장하는 필드들이 한 덩어리다
2. 덩어리마다 **이름을 붙여 본다.** 이름이 안 나오면 아직 경계가 아니다
3. 지표와 로그를 각자 **원인이 있는 쪽**으로 보낸다
4. 테스트를 따라 내려보낸다. 쪼갠 조각을 단독으로 검증할 수 없으면 쪼개다 만 것이다

쪼갠 뒤 원래 클래스에 남는 것은 **조율**뿐이어야 한다.

## 데이터와 협력자는 다르다

`Report` 의 필드 10개, `ReportEntity` 의 16개는 **속성이지 협력자가 아니다.** 쪼갤 대상이
아니라 그냥 그만한 데이터다. 그래서 검사기는 **스프링이 만들어 주는 빈만** 본다 —
협력자를 주입받는 자리가 거기뿐이다.

그 밖에 쪼개지 않아도 되는 경우:

- **그 자체가 목록인 것.** 레지스트리나 팩토리 모음은 필드가 많아도 책임이 하나다
- **쪼갠 조각에 이름이 안 붙는 것.** `XxxHelper`, `XxxManager` 밖에 안 떠오르면 경계를
  잘못 그은 것이다. 그냥 두는 편이 낫다

넘기기로 했으면 **혼자 판단하지 말고 사용자에게 이유를 말한 뒤** 커밋 앞에
`WIDE_CLASS=skip` 을 붙인다.

## 검사

커밋할 때 `commit-gate.sh` 가 자동으로 돌린다. 직접 돌리려면

```bash
bash .claude/skills/split-wide-class/scripts/find-wide-classes.sh
```

이미 커밋한 뒤에 보려면 범위를 준다 — `find-wide-classes.sh HEAD~1`.
기준을 바꿔 보려면 `MAX_FIELDS=5 MAX_CTOR_ARGS=3 bash ...` 처럼 앞에 붙인다.

**이번 변경이 건드린 파일을 통째로** 본다. 클래스의 폭은 줄이 아니라 파일의 성질이라,
한 줄만 고쳐도 그 클래스가 이미 넓으면 그때가 볼 때다.

## 검사기가 못 보는 것

- `src/test` 는 보지 않는다. 테스트 픽스처는 넓어도 되는 자리가 있다
- **빈이 아닌 클래스는 보지 않는다.** 협력자를 많이 든 일반 객체는 리뷰로 잡아야 한다
- **Lombok `@RequiredArgsConstructor` 는 생성자 인자를 0 으로 센다.** 생성자가 소스에 없다.
  그런 클래스는 필드 수로 걸린다
- 한 파일에 여러 클래스가 있으면 필드를 합쳐 센다. 파일 이름과 같은 생성자만 센다
- 들여쓰기와 `private` 으로 필드를 찾는 휴리스틱이라, 한 줄에 여러 선언을 쓰면 놓친다
- 상속으로 물려받은 필드는 세지 않는다
